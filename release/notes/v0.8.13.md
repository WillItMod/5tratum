# 5tratumOS 0.8.13 — Application installation, version reporting and host load

AxeLive and AxeBench installation now prefers the selected channel's current Store recipe. Bundled fallback recipes have explicit versions, so the rollback safety check no longer rejects them for missing metadata. AxeDoom's bundled local-build recipe has an explicit recipe version as well. Persistent rollback floors and Global Store review checks remain enforced.

Fresh installed-version status updates the desktop even while the release check is cached or unavailable. The canonical and legacy installed-build records are synchronized, and future updates reject a bundle whose embedded version disagrees with the selected release. A failed canonical metadata write cannot silently report a successful update through a shadowed fallback file. Update completion now waits for the new daemon process to start, avoiding a premature success report before restart.

Authentication retains up to 128 recent sessions per user, preserves recently active devices, and compacts legacy accumulated sessions at startup. Ordinary authenticated requests no longer scan the full collection on every call. Expired sessions remain invalid immediately. Older remembered logins outside the retention limit may need to sign in once. The reference node had accumulated roughly 130,000 sessions before this change, making each new login rewrite about 16 MB.

Application inventory now distinguishes a running container from an unhealthy application, displaying “needs attention” without automatically restarting intentionally paused Core processes.

AxePPC pool control now restarts its actual `pool` container, fixing the incorrect `ckpool` mapping used for difficulty changes and rollback.

The earlier bounded app inventory, accurate available-memory/swap/PSI reporting, Store Open fix, and orphan network-readiness cleanup remain included. The separate [GMKtec M6 support repair](https://github.com/WillItMod/5tratum/tree/main/support/gmktec-m6) remains targeted to its supported hardware; this update does not perform a global kernel upgrade or claim to cure every kernel fault or freeze.

Release validation and exact artifact checksums are recorded with the release artifacts. Both OS channels carry the same application code with their own build metadata. The independently signed Local AI 0.1.3 metadata is preserved. The OS update does not change mining allocations or replace disk images.

Validation: both exact channel archives installed successfully on the reference node using the existing updater. All four isolated AxeLive/AxeBench MAIN/DEV installation, UI and API checks passed without changing existing apps. Linux CI passed: 510 Python tests run (one intentional skip), 796 JavaScript tests passed, and rollback/shell checks passed. API, version, inventory concurrency and retained Local AI metadata were checked after install.

The companion [5tratMux 0.9.57 release](https://github.com/WillItMod/5tratMux/releases/tag/v0.9.57) adds exact Local AI percentages and named remainders, clear conflict explanations, miner compatibility fixes and notification retry backoff. Update Mux through its own updater to receive those application changes.
